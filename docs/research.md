# Queenfish · 调研（R1）

> 取数时间：2026-11-10。方法：对竞品网页做 HTTP 抓取 + 正文/价格表解析；搜索意图用百度联想词采样（联想词≠搜索量，只证明"有人这样问"）。
> 标注规则：`[实测]` = 本次抓到了页面原文；`[未取证]` = 页面动态渲染或需登录，未拿到；`[未联网验证]` = 纯推测，不写成结论。
> 本文件不承诺任何流量、排名、转化数字。

> Compressor.io 抓取被 Cloudflare 拦截，**未联网验证**，故不纳入结论。

三条可行动的结论：
1. **"压到指定大小"是唯一被竞品直接拿来收费的压缩能力**（压缩图、图好快都在卖），而我们的 PRD 把它放在 P2 —— 这是需求与范围的最大错位，见第 5 节待决策。
2. **"不上传"不是空白市场，但没人敢给证据**：docsmall 在图片压缩页自称浏览器本地处理 `[实测]`，Squoosh 一直本地但只有英文单张；国内其余全上传（TinyPNG/iLoveIMG/图好快/压缩图/改图鸭）。差异化要落在"**可验证**"，不是口号。
3. **中国站的通病是"功能墙 + 广告 + 上传"**：改图鸭 60+ 入口、压缩图首页塞 AI/证件照/PDF。单页只做压缩+转换，反而在加载速度和认知成本上有真实优势，且与 BRIEF 第 6 条性能门槛同向。

## 2. 需求地图（按搜索意图分组）

联想词样本（百度，2026-11-10 `[实测]`）：
`图片压缩到指定大小`｜`图片压缩到200k以内`｜`压缩图片到10k/50kb/2m以下`｜`png转jpg在线`｜`手机png转jpg`｜`图片转webp在线工具`｜`图片转WebP打包下载`｜`批量压缩图片免费软件`｜`手机图片压缩app`｜`图片压缩不改变清晰度`｜`图片压缩不到规定大小`

| 组 | 用户真正想要的结果 | 常见失败体验 | 我们能不能接 |
|---|---|---|---|
| 压缩到指定大小 | "上传系统要求 ≤200KB，压完刚好过审" | 压一档还是超标；只能换网站重试；只能裁尺寸毁构图；"压缩不到规定大小"本身就是高频联想词 | 能，但需二分试压（PRD 现列 P2） |
| png 转 jpg | 转完不变黑、不发糊、文件名可预期 | 透明区变黑/白底丢失；只能一张张下；转了反而变大；出图带水印 | 能（canvas 白底合成即可） |
| 转 webp | 更小且"对方能打开" | Safari/微信旧版打不开；动图变静图；批量转完要逐个存 | 能，但需在页面标明兼容边界 |
| 批量 | 一次拖几十张、打包下载、原名保留 | 免费版限 20/30 张；要登录；逐个点下载；处理时页面卡死 | 能（Worker + 逐个下载；zip 是 P1） |
| 手机端 | 微信里点开就能用、不装 App、能存相册 | 上传吃流量、等半天；iPhone 选到 HEIC 不支持；按钮小、误触 | 部分能（响应式；HEIC 明确不支持并给提示） |
| 隐私/敏感图 | 身份证、合同、商品图不外传 | 必须上传；"1 小时后删除"≠没被看过；隐私政策含糊；闭源无法验证 | 能，且这是我们唯一能"举证"的点 |

## 3. 差异化定位：3 个可选角度

**A. "压到指定大小"专家**
- 做什么：输入 200KB / 2MB，自动二分质量（最多 5 轮）逼近上限，附"已达标/最接近值"和再压一档。
- 为什么能赢：意图最硬、竞品把它做成付费点（图好快 5 元/张）；TinyPNG、iLoveIMG 都明确不给这个控制（iLoveIMG FAQ 直说不能调压缩级别）。
- 代价：结果有不确定性，文案不能承诺"必达标"；每张多跑 2–5 次编码，10 张批量的时间预算要重算（PRD P0-5 是 20s）；要处理"压到极限仍超标"的失败态。

**B. "可验证的零上传"**
- 做什么：开源 + 断网可完成一次压缩 + 页面自带"本次会话零外部请求"自检 + `CSP connect-src 'none'`；把验证步骤写成 3 行给人照做。
- 为什么能赢：竞品全在上传，"删除时间"是唯一安慰；docsmall 虽自称本地但闭源。可验证性是别人抄不走的叙事（抄了就得开源）。
- 代价：变现几乎为零（不能挂广告/统计）；"隐私"中文搜索热度明显低于"压缩到 200k"（联想词里几乎没有隐私类长尾），拉新主要靠工具词，隐私只负责留存与口碑。

**C. 手机/微信场景优先**
- 做什么：移动优先布局 + "存到相册"引导 + 批量结果一键连存 + 明确提示 HEIC 需先转 JPG。
- 为什么能赢：`手机png转jpg`、`手机图片压缩app` 是稳定联想词，而主流中文站是桌面思路、移动端按钮密集。
- 代价：iOS Safari 内存上限会杀掉大图批量（需限制并发与单张像素）；canvas 的 WebP 编码在 Safari 上的支持边界需 QA 实测（**未联网验证**）；"存相册"在 iOS 上是分享面板，做不到真正一键，容易做成承诺落差。

建议组合：**A 做钩子、B 做信任、C 做体验**，但首版只能选一个主叙事写进 H1 与 title —— 建议 A（决定 SEO 覆盖面），B 作为第二屏的证明，C 作为布局默认。

## 4. 增长渠道（可执行清单）

### 4.1 单页 SEO 结构
- 一个意图一个可索引段落，而不是一个意图一个薄页：`/` 承接"图片压缩"，`/png-to-jpg/`、`/to-webp/`、`/compress-to-200kb/` 若做，每页必须有该场景独有的说明与示例，否则会被判 doorway page（Google 垃圾内容政策）。
- title 模板：`图片压缩到 200KB 以内 · 不上传 · 本地处理`；H1 只放一个意图；首屏 200 字内出现"不上传/本地"与支持格式。
- 内链：3 个转换页互链 + 回首页；面包屑与 `BreadcrumbList` 一致。
- 合规风险：低。唯一红线是不堆竞品名（如"TinyPNG 替代"可做对比页但需真实对比、不贬损，否则涉不正当竞争）。

### 4.2 sitemap 与 robots
- `sitemap.xml` 手写静态文件，只放 canonical URL，`lastmod` 用真实改动日期；`robots.txt` 允许全站、给 `Sitemap:` 绝对地址；**不要** Disallow CSS/JS（会被判渲染不全）。
- 提交：Google Search Console + Bing Webmaster Tools（都支持 GitHub Pages 域名验证）。百度站长平台可交，但 GitHub Pages 在国内的可达性不稳定，**不承诺百度收录** `[未联网验证]`。
- 合规风险：低；注意别用"sitemap ping"老接口做自动提交（Google 已废弃该端点）。

### 4.3 结构化数据
- 建议：`WebApplication`（name / applicationCategory=MultimediaApplication / operatingSystem=Any / offers price 0）+ `BreadcrumbList`。这两类仍会被正常解析。
- 不建议把宝押在 `FAQPage` / `HowTo`：Google 2023-08 起 FAQ 富媒体只对权威政府与健康站展示、HowTo 桌面端已下线（[官方公告](https://developers.google.com/search/blog/2023/08/howto-faq-changes)）。写了不亏，但别把它算进 KPI。
- 合规风险：低。红线是别标记页面上不存在的 FAQ（会被判垃圾结构化数据）。

### 4.4 冷启动第一周（每天 1–2 个动作）
| 天 | 动作 | 具体做法 | 合规风险 |
|---|---|---|---|
| D1 | 上线 + 索引 | 仓库 public、Pages 生效、GSC/Bing 验证并交 sitemap；README 写清"零上传、如何自证" | 低 |
| D2 | GitHub 自身流量 | 仓库 topics 选 `image-compression`/`privacy`/`webp`；在 README 放截图与"断网测试"步骤 | 低；勿刷 star |
| D3 | 开发者社区 | V2EX「分享创造」一帖：只讲"为什么不上传"和一个真实数字（如首屏 KB），不喊口号 | 中：V2EX 反感纯推广，需账号有历史、只发一次 |
| D4 | 中文内容平台 | 少数派 Matrix 投稿一篇"我为什么把图片压缩做成纯前端"，附可验证步骤 | 中：需原创、编辑可能拒；不得一稿多投刷量 |
| D5 | 工具目录 | AlternativeTo、Product Hunt（上线版）、`awesome-web-tools` 类仓库 PR | 中：目录站多为 nofollow，SEO 收益≈0；PR 需遵守各清单贡献规则，勿群发 |
| D6 | 短视频/图文 | 小红书/即刻发"200KB 报名照怎么压"实操，**不放外链**，评论区再给 | 中高：平台限导流；必须标"自荐"，否则违《互联网广告管理办法》可识别性要求 |
| D7 | 复盘 | 看 GSC 展现词，决定第 2 周做 `/compress-to-200kb/` 还是 `/png-to-jpg/` | 低 |

不要做：买外链、批量群发论坛、互点、伪装用户自问自答（均违反 Google 垃圾政策或平台规则，且新站最容易被连带降权）。

## 5. 风险清单（诚实版）

1. **平台政策**：GitHub Pages 有硬边界 —— 站点 ≤1GB、软带宽 100GB/月、软构建 10 次/小时（[官方 Limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)）。纯静态工具站几乎不可能撞上，但一旦要放广告/赞助，需自行确认 GitHub 服务条款对商业用途的界定 `[未联网验证]`。
2. **国内可达性**：GitHub Pages 无 ICP 备案，境内访问速度与稳定性不受我们控制，且可能间歇不可达 `[未联网验证]`。因此中文流量预期必须打折，不能把"国内主流工具"当默认假设。
3. **隐私承诺的可验证性**：只要后续加一条第三方统计/字体/CDN，"零上传"叙事立刻破产。可验证手段只有三样：开源代码、断网演示、自动化断言（Playwright 拦截 `request` 事件断言无第三方域）。建议把这条做成 CI 检查，而不是文案承诺。
4. **广告法红线**：不能用"最快/第一/无损/100%"。注意竞品普遍在用（压缩图 title 直接写"无损压缩 90%" `[实测]`），跟着写会踩《广告法》第九条极限词与虚假宣传。BRIEF 第 8 条已覆盖，执行时逐字检查 title/description/OG。
5. **SEO 冷启动**：新域名 0 权重，工具词竞争者是十年老站；AI 摘要持续压缩点击。合理预期是 3–6 个月才有稳定自然流量，**不给具体数字**；前 4 周更该看"GSC 是否有展现"而不是"有没有排名"。
6. **技术边界被高估**：canvas 只能可靠编 JPG/WebP；AVIF/HEIC 需 wasm，与首屏 80KB 冲突（PRD 已排除，判断正确）。Safari 的 `toBlob('image/webp')` 支持情况需 QA 实测 `[未联网验证]`，若返回 PNG 必须在 UI 里降级提示，不能静默出错。
7. **商标与对比**：做"vs TinyPNG"页可以做，但必须真实跑分、注明测法与日期，否则风险高于收益。

## 6. 给指挥官的三条输入（详见汇报"待决策"）

- P2 的"目标体积模式"与最强搜索意图冲突，建议至少提到 P1。
- "批量打包 zip"在中文站是付费点（图好快/压缩图会员），P1 合理，但需先确认 vendored 体积。
- 隐私叙事需要可验证证据（开源 + 断网 + CI 断言），否则就只是又一句"我们不上传"。
